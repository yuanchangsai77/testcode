# 核心运行时：Shell 会话生命周期

## 范围

`shell_exec` 为一个 testcode 交互会话维护一个串行 Bash 进程。它用于保留当前目录和
环境变量；它不是终端模拟器，也不提供文件系统或网络隔离。

本文档描述当前实现的生命周期与安全边界。工具字段语义见
[Tool 字段契约](../reference/tool-contract.md)，整体运行时职责见
[总体架构](../architecture.md)。

## 进程组

在 POSIX 系统上，Bash 启动于独立会话和进程组。由 Bash 启动的普通前台或后台子进程
属于同一组，因此 testcode 可以按会话整体管理它们，而不是只管理 Bash 的主进程。主动
创建独立会话或进程组的程序不在这一保证范围内。Windows 目前只终止 Bash 主进程，
不保证回收其后台子进程。

## 终止规则

以下事件会关闭 Shell 会话：

- 用户在输入提示符处按 Ctrl+C，或输入 `exit`/`quit`；
- 用户在模型调用或工具执行中按 Ctrl+C；
- `shell_exec` 命令超时；
- 运行结束且不需要保留工具状态，或切换到另一个会话。

关闭时先向进程组发送终止信号，短暂等待；仍未结束时发送强制终止信号。命令超时或
Shell 协议出错时，会立即替换为新的干净 Bash；其他关闭情形则在下一次 `shell_exec`
调用时创建新的 Bash。

## 并发边界

一个 `ToolRegistry` 只维护一个 Shell 会话，命令按顺序执行。不同 testcode 进程或
不同注册表可各自拥有独立 Bash；后续若引入多会话并发，应设置全局进程数和资源上限。

## 安全边界

进程组只能解决中断和清理，不能阻止命令访问宿主机文件、网络或系统服务。需要安全
隔离时，应使用容器或 Linux 沙盒，并将工作区与获准外部目录显式挂载进去。
