# Subagent 会话集群

## 文档职责

本文定义本地 subagent 第一阶段的会话关系、启动来源和协作边界。它不定义远程 A2A wire
协议，也不把会话历史或未来记忆系统重新命名为 subagent。

## 1. 核心边界

一个主会话可以拥有多个独立子会话。主会话和子会话组成 `SessionCluster`，由会话集群协调器
管理。每个成员仍是普通的持久化会话，独立拥有消息、run、tool history、状态和后续的 context
budget；集群不是一个共享大 prompt。

会话之间不建立直连对话通道，也不能读取另一个成员的原始消息或工具历史。协作只经过集群的
公共状态空间，成员向其中发布有界的状态、发现、阻塞、验证结果或 artifact 引用。公共空间保存
来源会话和递增 revision，供监督器观察和恢复。

这三个概念必须分开：

- 历史会话是曾经发生过的交互记录，用于恢复原会话。
- 会话镜像是不可变的启动材料，用于创建新的独立会话，不代表运行中的会话。
- 记忆是未来可检索、可治理的长期知识，不承担成员发现、任务状态或集群协调。

## 2. 启动来源

子会话有且只有一种明确的启动来源：

- `inherit`：在创建时复制主会话当前的工作目录、消息快照和已激活能力。之后两者独立演进。
- `fresh`：使用调用方给出的新会话配置；未指定工作目录时只继承主会话工作目录。相对目录以
  主会话工作区为基准解析，越出主会话工作区的目录会被拒绝。
- `image`：从会话镜像仓库读取一个已保存模板，再创建新会话。镜像本身不被修改；镜像保存的
  工作目录同样不能扩大主会话的工作区根目录。

每个子会话记录父会话、集群、启动来源和可选镜像标识，以便审计和未来映射到 A2A 的本地
Workflow 投影。创建后成员进入 `ready`；`SubagentRunner` 原子领取成员，为每个成员创建隔离 runtime，
并发执行委派任务，并把有界结果或失败写回公共状态。

后台结构化写入授权由 runner 在成功领取成员后签发，并绑定 cluster、child session、attempt 和
工作区。单独设置后台运行模式不产生写入授权；runtime 在执行前必须重新校验请求与授权范围一致。

同一交付物的反馈、修复或补充任务优先使用 `subagent_resume` 续跑原成员。续跑不创建新 session，
而是保留原会话消息、run trace、能力和已知问题，更新当前任务并把成员从终态重新置为 `ready`。
只有任务需要隔离上下文、并行独立探索、原会话记录损坏，或用户明确要求新成员时才使用
`subagent_spawn`。`running` 成员不能被重复续跑；必须先完成或取消当前 attempt。

主会话批准 `subagent_run_ready` 后，`confirm` 模式下的子会话获得仅限本次委派、仅限其
工作区的普通结构化写入权限。该授权允许 `patch`，不自动允许 Shell、测试、网络或破坏性
动作；这些动作在无交互后台中会使成员进入 `blocked`，不能伪装成完成。`readonly` 模式不
授予写权限。审批代理机制见[审批代理与委托授权](approval-delegation.md)。首版子会话不再暴露
会话编排工具，避免无监督递归委派。父会话中的四个生命周期工具也不常驻初始工作台，而是
通过 `local:subagents` 工具箱按需打开和激活。

## 3. 公共状态空间

公共状态空间是 append-only 协作面，不是聊天记录。首版条目包含：

- 条目标识、作者会话和类型。
- 有界摘要与可选 artifact 引用。
- 创建时间和集群 revision。

成员生命周期单独维护为 `ready`、`running`、`blocked`、`completed`、`failed` 或 `cancelled`。
只有委派目标正常完成才能进入 `completed`；等待审批、权限不足和进度耗尽进入 `blocked`，
运行时异常进入 `failed`；用户中断进入 `cancelled`。每次续跑增加 attempt，历史 run 不被覆盖。
公共状态写入使用文件锁和原子替换，避免多个本地 worker 覆盖彼此更新。消费者应按条目标识幂等
处理，并以较新 revision 为准。终态和最终公共状态在同一次带 attempt 条件的原子更新中提交；
取消或续跑已经改变 attempt 后，迟到 worker 不能再提交旧结果。

## 4. 交付信任与验证边界

子会话的 `completed` 是一项结构化交付声明，不是无限信任，也不要求主会话重新实施一次任务。
主会话默认复用子会话的摘要、变更范围和验证结果，不再逐文件通读产物。只有以下情况才做有界验证：

- 子会话没有给出产物或验证证据；
- 摘要、公共状态和工作区状态互相冲突；
- 用户明确要求复核；
- 变更涉及安全边界、破坏性动作或不可逆外部状态。

验证应针对声明进行，例如运行一个测试或读取报错附近的片段；不能以“确认一下”为由完整重做。
验证失败后的默认动作是续跑原子会话，并把失败证据作为新任务附加给它。

最终 handoff 至少携带终态、文本摘要、attempt、成功修改的文件列表、结构化测试结果和 artifact
引用。`subagent_run_ready` 的直接结果与 `subagent_status` 读取的公共状态使用同一组有界字段。

## 5. 超时、重试与中断

后台子会话使用独立且较小的模型重试预算。一次模型请求超时后只做有限重试，失败即发布 blocker，
把恢复选择交还主会话；不能把主会话的长重试预算原样复制给每个并发 worker。

`subagent_run_ready` 收到用户中断时必须取消尚未开始的成员、向正在运行的 runtime 传播取消信号，
并把相应成员记为 `cancelled`。被取消的旧 attempt 即使稍后返回，也不能覆盖较新的成员状态或交付。

## 6. A2A 演进

本地成员标识、生命周期和公共状态以后可以投影为远程 A2A Task、状态更新和 Artifact，但本地
记录不冒充远端权威状态。A2A Adapter 只能读取或写入这一稳定边界，不能获得跨会话原始历史的
隐式访问权。

## 7. 第一阶段验收范围

- 一个主会话可创建一个集群并申请多个子会话。
- 三种启动来源都创建独立持久化会话并保留来源关系。
- 会话镜像可保存、读取、列出，并作为新会话启动材料。
- 主 Agent 可通过工具批量创建成员，再由 runner 并发执行所有 `ready` 子会话。
- 同一成员可通过 `subagent_resume` 携带原上下文继续修复，且不会生成新的 session id。
- 每个子会话使用独立模型、工具、日志和权限 runtime；执行完成、阻塞或失败自动进入公共状态和成员终态。
- 后台模型重试有独立上限，用户中断可把成员可靠收敛为 `cancelled`。
- 只有集群成员能发布公共状态；未知成员和越界 artifact 引用被拒绝。
- 暂不包含跨进程常驻 worker、进程崩溃后自动续跑、交互式审批代理、成员直聊和远程 A2A transport。
