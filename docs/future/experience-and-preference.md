# 未来平台经验与偏好

## 文档职责

本文定义可复用经验、用户偏好、检索注入和能力晋升的权威语义，并明确它们在 Plane、Layer 和运行域
中的位置。它不重复定义 Conversation/Workflow 的恢复语义、Policy 的授权规则或 Skill 的包格式。

## 1. 目标与边界

平台需要把一次代表性工作、长期反复排查后确认的关键解法，以及用户明确表达的稳定偏好，在保留
来源和适用范围的前提下转化为以后可检索的信息。

`[不变量]` 经验不是权限，检索命中不是事实证明，历史成功也不能跳过当前 Policy、授权、环境检查
和结果验证。模型可以提取、归纳和推荐内容，但不能直接成为经验或偏好的权威存储。

以下状态必须分离：

| 状态 | 用途 | 不用于 |
| --- | --- | --- |
| Conversation hot/warm/cold | 当前会话连续性、恢复和完整历史引用 | 自动形成长期结论 |
| Workflow/Artifact archive | 保存执行证据、日志、结果和审计材料 | 直接注入每次模型上下文 |
| Experience | 保存有适用条件、证据和验证状态的可复用知识 | 授予能力或绕过验证 |
| Preference/Profile | 保存用户或项目声明的选择、默认值和交互偏好 | 保存实时状态、凭据或外部事实 |
| Skill/Plugin | 封装经过维护、测试和发布的可执行方法 | 承接未经验证的临时经验 |

## 2. Plane 规划

### Agent Plane：权威所有者

Agent Plane 的 Knowledge Runtime 管理 Experience 和推断偏好候选，Profile Store 管理已经生效的
Preference/Profile；首个实现可以位于同一进程，但二者保持独立状态和生命周期。

- Experience Store 保存候选、有效、已取代、已撤销和已过期的经验版本。
- Profile Store 保存明确偏好和用户已经确认的推断偏好。
- Knowledge Runtime 保存待确认的推断偏好候选；确认后通过 Profile 契约写入，不能直接提升状态。
- Context Assembly 只取得与当前目标相关、经过范围和权限过滤的只读投影。
- Orchestration Runtime 在 Workflow 完成和验证后触发经验候选生成，并记录实际使用反馈。
- Trust Runtime 对读取、写入、共享、遗忘和能力晋升执行 Policy。

### Model Plane：可替换的计算资源

Model Plane 可以为摘要、结构提取、相似度、重排和冲突解释选择模型，但不拥有经验、偏好、索引
版本或用户画像。更换 Provider 后，记录身份、版本和撤销状态保持稳定。受限内容能否送往某个模型
必须在路由前决定。

### Device Plane：证据来源而非知识所有者

Device Plane 可以提供执行结果、Observation、设备与环境版本等证据。它不直接写入个人 Profile，也
不把一次设备结果宣布为长期经验。涉及现实状态的经验必须携带有效期或重新观察条件。

### A2A 边界

远程 Agent 只接收完成任务所需的最小 Experience/Preference 投影，默认不能检索用户的完整个人
知识库。远程 Agent 返回的总结、方法或 Artifact 先作为外部来源的候选内容进入本地验证，不能直接
写入 Experience Store、Profile Store 或发布为 Skill。跨域投影必须绑定任务、受众、用途和期限。

### 主交互模型边界

主交互模型只接收 Context Assembly 形成的 Experience/Preference 只读投影。它可以建议“这次解法
值得记住”、生成候选内容或向用户解释偏好冲突，但 Experience 生命周期由 Knowledge Runtime 管理，
有效 Preference/Profile 由 Profile Store 管理，Trust Runtime 只裁决这些操作是否允许。模型发起新
Workflow 时，历史经验仍然只是规划输入，不成为 ExecutionAttempt 的成功证明。

## 3. Layer 规划

| Layer | 经验与偏好职责 |
| --- | --- |
| L6 Experience | 提供“记住、不要记住、忘记、修正、为何推荐”和冲突确认入口 |
| L5 Composition | 组织个人、项目、环境和场景 Profile；定义经验集合、作用范围与优先级 |
| L4 Intelligence | 提取候选经验、概括根因、生成检索查询、相似度排序和冲突解释 |
| L3 Orchestration | 管理候选、验证、发布、取代、撤销、检索和使用反馈的生命周期 |
| L2 Contract | 定义 Experience、Preference、Evidence、Query、Retrieval Result 和 Promotion 的稳定语义 |
| L1 Runtime & Adapter | 连接全文/向量索引、Profile Store、Archive、Artifact 和 Skill 发布器 |
| L0 Infrastructure | 提供数据库、文件、索引、加密、备份和模型计算资源 |

`[不变量]` L4 只能提出内容和相关性判断；L3 决定生命周期，Trust Runtime 决定是否允许持久化、读取
或共享，L5 决定组合范围。L6 不直接操作底层索引。

## 4. Experience 最小语义

Experience 描述“在什么条件下，什么观察和证据支持什么结论或方法”。最小稳定语义包括：

- 稳定 identity、版本、状态和所有者。
- 类型，例如诊断、操作方法、决策依据、已知限制或失败模式。
- 触发特征、适用范围和明确的不适用条件。
- 问题表现、关键根因、有效方法，以及有价值的失败尝试。
- 验证方式、验证结果、可信度和最近验证时间。
- 来源 Workflow、ExecutionAttempt、Artifact 或用户陈述的引用。
- 项目、平台、版本、设备、数据域等环境约束。
- 保留、过期、撤销和取代关系。

原始日志和大型内容留在 Archive/Artifact 中；Experience 只保存有界描述和稳定引用。删除或失去访问
权的证据不能通过已有索引旁路继续泄露。

## 5. 经验固化生命周期

```text
Workflow 完成或用户明确要求记住
  → 产生 Experience Candidate
  → 绑定来源、适用条件和验证结果
  → 去重并检查与现有经验的冲突
  → 按风险自动接受或请求用户/维护者确认
  → 发布为可检索 Experience
  → 后续使用后记录结果
  → 修订、降低可信度、取代、过期或撤销
```

候选触发信号可以包括：问题反复出现、排查成本显著、多个常见方案失败、找到可解释根因、产生了
可重复验证的修复，或用户明确标记为代表性工作。触发信号只产生候选，不保证内容正确。

`[当前推荐]` 只有具备客观验证结果的低风险经验可以按 Profile 自动发布；缺少证据、包含敏感内容、
会改变高风险操作或与现有记录冲突时必须保持候选并请求确认。

Experience 晋升为 Skill/Plugin 是独立发布流程，需要明确维护者、结构化输入输出、风险声明、测试、
版本和回滚方式。经验可以指导模型，Skill 才是受能力仓库治理的可执行资产。

## 6. Preference 与 Profile 生命周期

Preference 至少区分：

- 用户明确声明的长期偏好。
- 从重复选择推断、尚待确认的候选偏好。
- 只对当前 Conversation 或 Workflow 生效的临时选择。
- 由组织、项目或安全要求给出的 Policy；它不是普通偏好。

最小语义包括主体、作用范围、值、来源、明确/推断属性、可信度、版本、有效期和撤销状态。敏感、
付费、数据出域、权限或现实副作用相关选择不能仅凭行为推断升级为长期偏好。

`[不变量]` Preference 不能扩大 Policy 允许的权限。当前明确用户请求优先于同范围的普通默认偏好，
更具体且仍有效的 Profile 范围优先于一般范围；安全与组织 Policy 始终独立裁决。发生冲突时必须
保留来源和版本，不能静默覆盖。

## 7. 检索与上下文注入

```text
当前目标、项目和环境
  → 按主体、信任域、范围、版本和权限硬过滤
  → 全文/结构/向量候选检索
  → 相关性、新鲜度、证据和历史效果排序
  → 去重与冲突标记
  → 形成有预算、带来源的 Context Projection
  → 模型建议，Runtime/Policy 决定是否执行
```

每次注入必须记录所用 Experience/Preference identity 和版本，以便复现决策、接受用户纠正并判断
旧经验是否导致失败。向量索引只是派生投影，权威记录仍在 Store；索引可以重建，不能拥有独立的
删除或授权语义。

检索不到合适经验时应正常执行当前 Workflow，不能把相似度不足解释成不存在风险。相互冲突、已经
过期或环境不匹配的经验默认不作为行动依据，但可以作为带警告的排查线索。

## 8. 隐私、共享与遗忘

- 默认按用户、项目和信任域隔离；跨范围共享需要明确目的和最小投影。
- 个人偏好、私有代码经验和家庭 Observation 不默认发送给远程 Agent 或外部模型。
- 用户可以查看记录来源、纠正、撤销、导出或请求遗忘。
- 遗忘必须覆盖权威记录、可重建索引和未再被合法引用的副本；必要审计只保留最小不可逆证明。
- 外部内容和 A2A 返回内容带来源与不可信标记，不能通过“保存为经验”获得更高执行权限。

## 9. 验收不变量

- 模型切换后 Experience、Preference identity、版本和撤销状态不变。
- 未授权主体无法通过检索、索引、摘要或 A2A 投影获得记录。
- Experience 命中不能跳过 Capability activation、Policy、Approval 或效果验证。
- 推断偏好不能自动改变敏感、付费、数据出域或有物理副作用的行为。
- 旧版本、迟到反馈和远程结果不能覆盖新的有效记录或已撤销状态。
- 每条被用于行动的经验都能追溯到版本、来源、适用范围和验证状态。
- Experience 到 Skill 的晋升必须经过能力仓库的准入、测试和版本治理。
