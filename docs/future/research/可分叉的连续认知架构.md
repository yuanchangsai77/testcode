# 可分叉的连续认知架构

## Continuous Branchable Cognition Architecture

> 文档定位：本文是独立的长期架构研究，不定义当前 subagent 运行时契约，也不属于
> “Subagent 上下文、公共空间与委托权限安全审查”修复范围。当前实现边界以 `docs/core/`
> 和 `docs/reference/` 下的正式文档为准。

## 一、核心问题

现有大模型大多仍然遵循一种非常“对话式”的计算范式：

**输入一段 Prompt → Transformer 读取 → 自回归生成大量 Token → 结束。**

这种模式非常适合问答，但如果目标是构建一个长期运行、持续感知现实世界的 AI，就会遇到几个根本问题。

第一，**模型的思考与语言输出高度耦合**。

模型想增加推理深度，通常意味着：

> token → token → token → token

每一步推理都需要通过自然语言或类似 token 的离散序列表达出来。

这导致推理过程天然受到自回归串行速度限制。

第二，**长期输入会导致 KV Cache 持续膨胀**。

如果一个 AI 持续监听几小时、几天甚至几个月，不可能把全部历史 token 永久留在 Transformer 的 active context 中。

第三，现实世界不是一个一次性 Prompt。

现实输入本质上是：

> 一个持续、异步、带时间间隔的事件流。

有人讲话时有输入，没有人讲话时没有输入；不同输入之间的间隔本身也携带信息。

第四，大量历史信息并不是每时每刻都值得使用最高计算精度。

人类也不会把一生经历全部同时放入工作记忆，而是：

> 近期保持高分辨率，远期逐渐抽象，需要时重新回忆局部细节。

因此，这套架构希望解决的并不是单纯：

> 如何让 Transformer 支持 1M、10M Token。

而是一个更根本的问题：

> **如何让 AI 持续经历无限长的世界，同时保持有限的活跃计算状态。**

---

# 二、核心思想

整套架构可以概括为五个原则：

## 1. 持续感知，而不是一次性 Prompt

AI 面对的是：

**Continuous Event Stream**

而不是：

**Prompt → Answer**

---

## 2. 感知、思考、输出三者解耦

模型可以：

* 一直听；
* 但不一直深度思考；
* 更不需要一直生成 Token。

即：

**Input ≠ Think ≠ Decode**

---

## 3. 历史可以无限增长，工作记忆不能无限增长

长期经历进入外部记忆和压缩状态。

Transformer 只保持有限的 active context。

---

## 4. 思考是事件驱动的

一个低成本控制器持续判断：

* 是否需要思考；
* 是否需要 Fork；
* 应该调用多久以前的信息；
* 应该思考多深；
* 是否需要中断已有推理；
* 是否需要重启某条思路。

---

## 5. Token 只是通信格式，不应该成为思考本身的时钟

理想状态下：

> 感知、状态更新、记忆检索、路由、Fork、Merge、内部推理都可以在 latent/control space 中进行。

只有真正需要：

* 给用户说话；
* 调工具；
* 调 API；
* 输出结构化结果；

时才进行 Token Decode。

---

# 三、总体架构

整个系统可以拆成六个核心部分：

```text
                     REAL WORLD
                         │
                asynchronous events
                         │
      content / source / timestamp / Δt
                         │
          ┌──────────────┼──────────────┐
          │              │              │
          ↓              ↓              ↓
     Raw Archive      Mamba/SSM    Recent Transformer
     原始事件存储      Temporal State    bounded KV
                         │
                         ↓
                   CONTROL SIGNAL
                         │
                         ↓
                  Runtime Scheduler
                         │
                 Context Builder
               /        │        \
              ↓         ↓         ↓
         Recent KV   Latent Memory  Raw Retrieval
               \        │        /
                \       │       /
                 Transformer Snapshot
                         │
              ┌──────────┼──────────┐
              ↓          ↓          ↓
           Branch A   Branch B   Branch C
              │          │          │
              └──────────┼──────────┘
                         ↓
                       MERGE
                         │
                ┌────────┼─────────┐
                ↓        ↓         ↓
              SIGNAL    TOOL      TOKEN
```

---

# 四、现实输入：从 Token Sequence 变成 Event Stream

传统模型看到：

```text
token₁ token₂ token₃ token₄ ...
```

这隐含着一个假设：

> Token 是连续出现的。

但真实世界不是这样。

例如：

```text
10:00:00  用户：这个路线……
10:00:03  用户：我觉得坡度有问题
10:00:09  用户：你怎么看？
```

真正的输入应该更像：

```text
Event {
    content
    source
    modality
    timestamp
    delta_t
}
```

其中：

**Δt 是天然的时间信号。**

例如：

```text
Δt = 20ms
→ 连续语音

Δt = 700ms
→ 句间停顿

Δt = 5s
→ 对话沉默

Δt = 2min
→ 可能发生主题边界

Δt = 8h
→ session boundary

Δt = 30day
→ 长期记忆层级
```

因此时间不再只是 Position Encoding 的附属信息。

它成为模型认知状态的一部分。

---

# 五、Mamba / SSM 的真正定位

这里 Mamba 不应该作为 Transformer 前面的硬过滤器。

错误架构是：

```text
Input
 ↓
Mamba
 ↓
过滤后的内容
 ↓
Transformer
```

因为只要 Mamba 判断错一次：

> 重要信息就可能永久消失。

正确架构应该是：

```text
                     ┌── Raw Archive
Input Event ─────────┤
                     ├── Transformer
                     │
                     └── Mamba / SSM
                              │
                            Signal
```

Mamba 的角色不是：

> 决定 Transformer 能不能看到什么。

而是：

> **维护连续世界状态，并决定系统应该如何计算。**

---

# 六、Mamba = Temporal Cognitive Scheduler

Mamba 可以持续维护一个固定或近似固定大小的状态：

```text
S_t = F(S_t-1, x_t, Δt)
```

这个 State 不追求保存每一个原始 Token。

它保存的是：

> 过去发生的一切综合起来，现在系统处于什么状态。

例如：

* 当前在和谁说话；
* 当前是什么任务；
* 对方是否仍然在讲话；
* 当前话题是否发生改变；
* 某个任务是否中断；
* 最近是否出现重要异常；
* 当前有哪些 Branch 正在运行；
* 是否有 Branch 已经过时；
* 是否需要深度推理。

所以可以理解为：

> Transformer 保存细节，Mamba 保存连续状态。

---

# 七、Signal：整个系统的核心控制接口

Mamba 不需要不断输出自然语言。

它可以输出一个低带宽 Control Signal。

Signal 可以包括：

```text
NONE
LISTEN
STORE
THINK
FORK
MERGE
REBASE
RESTART
CANCEL
RETRIEVE
TOOL
RESPOND
INTERRUPT
```

但 Signal 不应该只是一个简单的离散脉冲。

真正完整的 Signal 更像一个计算控制包。

例如：

```text
Signal {
    action: FORK

    mode: spatial_reasoning

    recent_window: 30s

    memory_query:
        topic = "route planning"
        time_scope = "3 months"
        top_k = 6

    depth: 12

    branches: 3

    interrupt_on_new_info: true
}
```

Signal 实际上控制五件事情：

### 什么时候思考

### 思考什么

### 回看多久

### 开多少条思路

### 花多少计算资源

---

# 八、Transformer 的三种状态

Transformer 不应该只有：

> Running / Not Running

而应该拆成三个阶段。

## 1. LISTEN

持续接受最新输入。

更新有限长度 KV。

不进行长 CoT。

不输出语言。

---

## 2. THINK

收到 Signal 后：

* 截取 Snapshot；
* 构建上下文；
* 启动额外计算；
* Fork 多个思考 Branch。

---

## 3. DECODE

只有真正需要：

* 对外回答；
* 调工具；
* 输出命令；

时才开始自回归 Token Decode。

因此：

```text
LISTEN ≠ THINK ≠ DECODE
```

这是整个架构的重要分离。

---

# 九、主 Transformer 必须持续运行，但 KV 必须有界

主 Transformer 不能：

```text
Day 1 KV
+
Day 2 KV
+
Day 3 KV
...
```

无限增长。

而应该使用：

> **Bounded Working Context**

例如：

```text
最近 16K / 32K / 64K Token
```

形成一个滑动的高分辨率工作记忆。

因此：

```text
Experienced History = months / years

Active KV = 32K
```

两个概念彻底分离。

最核心原则是：

> **模型经历过多少信息，不应该等于它当前必须 Attention 多少信息。**

---

# 十、RoPE 只负责近期连续序列

Recent Transformer 仍然使用正常：

```text
Token Embedding
+
RoPE
+
KV Cache
```

因为近期语言中的顺序非常重要。

例如：

```text
A → B → C
```

与：

```text
C → B → A
```

语义不同。

所以：

> **Recent Context 是一个 Sequence。**

Sequence 需要明确位置关系。

---

# 十一、长期记忆不应该继续保存成普通 Token

当信息逐渐离开 Recent Window 后，不应该简单地永久保存：

```text
Token₁
Token₂
Token₃
...
Token₁₀₀₀₀
```

然后未来重新塞回 Transformer。

更合理的是经过：

```text
Raw Sequence
    ↓
Episode Detection
    ↓
Abstraction
    ↓
Memory Consolidation
    ↓
Latent Memory Object
```

形成碎片化、抽象化的记忆单元。

---

# 十二、远端记忆不使用传统 RoPE

长期 Memory 不再是：

```text
M1 → M2 → M3 → M4
```

这样的连续序列。

而更像：

```text
{M17, M241, M92, M6}
```

一个可检索记忆集合。

因此它不再需要知道：

```text
position = 812732
```

或者：

```text
RoPE(position)
```

但这并不意味着长期记忆不需要时间。

应该区分：

> **Position ≠ Time**

长期 Memory 可以保存：

```text
timestamp
age
duration
episode_id
before/after relationship
causal relation
```

甚至单独做：

```text
Time Embedding
```

因此：

### Recent Tokens

使用：

**RoPE / positional relation**

### Long-Term Memory

使用：

**temporal metadata / time embedding**

---

# 十三、长期记忆应该以 Latent Object 而非自然语言保存

传统 RAG：

```text
文字
 ↓
Embedding
 ↓
Vector Search
 ↓
把文字重新塞回来
```

这里可以更进一步。

Memory 应该拆成：

```text
Memory {
    retrieval_key
    latent_value
    metadata
    source_pointer
}
```

其中：

## Key

负责：

> 找到这段记忆。

通常可以是 embedding。

---

## Value

负责：

> 真正恢复模型内部记忆。

不一定需要自然语言。

可以直接是：

```text
latent vector
```

或者：

```text
latent slots
```

---

# 十四、Memory Value 不一定只有一个 Vector

复杂记忆压成一个向量可能损失太大。

可以设计成动态分辨率。

例如：

```text
普通事件
→ 1 latent slot

中等重要事件
→ 4 latent slots

复杂会议
→ 16 latent slots

重要长期知识
→ 32 latent slots
```

因此形成：

> **Adaptive Memory Resolution**

这和多尺度物理计算很类似：

简单区域低分辨率。

重要区域高分辨率。

---

# 十五、Memory 分为 Episodic 和 Semantic

这里“定格”需要分两种。

## Episodic Memory

表示：

> 当时发生了什么。

例如：

```text
2026-08-10
曾讨论某个架构
```

这一类 Memory 应该尽量 immutable。

因为过去已经发生。

---

## Semantic Memory

表示：

> 从多次经验中得出的抽象理解。

例如：

```text
这个用户更喜欢哪类技术方案
某个项目当前采用什么架构
某类问题的解决经验
```

Semantic Memory 可以随着新经验不断更新。

因此：

```text
Episode 1 ─┐
Episode 2 ─┼──→ Semantic Memory
Episode 3 ─┘
```

---

# 十六、必须保留 Raw Archive

Latent Memory 是：

> 模型对过去的理解。

而不是：

> 过去本身。

因此不能完全依赖 Latent Memory。

必须存在：

**Raw Archive**

保存原始：

* 文本；
* 音频；
* 图像；
* 视频；
* 工具返回；
* 文件；
* sensor data。

长期 Memory 应保留：

```text
source_pointer
```

如果模型需要：

> “对方当时到底说的是 35% 还是 53%？”

就不应该依赖抽象后的 Memory。

而应该：

```text
Memory
 ↓
source_pointer
 ↓
Raw Archive
 ↓
重新读取原始证据
```

---

# 十七、完整 Memory Hierarchy

可以形成四层记忆：

```text
                      NOW
                       │
                       ↓

L0 Recent Working Memory
─────────────────────────
Raw Token
RoPE
KV Cache
秒 / 分钟
最高精度

          ↓ consolidation

L1 Episodic Latent Memory
─────────────────────────
Memory Fragment
Latent Slots
Timestamp
分钟 / 天

          ↓ abstraction

L2 Semantic Memory
─────────────────────────
Concept
Relation
Learned State
月 / 年

          ↓ reference

L3 Raw Archive
─────────────────────────
Text
Audio
Image
Video
Logs
长期冷存储
```

# 十八、Fork：从当前认知主干长出的临时思考

主 Transformer 可以理解成现实世界的：

> Main Branch

它持续监听现实。

例如：

```text
Reality Main
────────────────────────────────→
```

当出现：

```text
SIGNAL: FORK
```

时：

```text
                 Snapshot S₀
                  /   |   \
                 /    |    \
           Branch A Branch B Branch C
```

这些 Branch 不复制整个模型。

共享：

```text
Model Weights
```

复制的是：

```text
Runtime State
Context
Branch State
```

因此更像操作系统：

```text
fork()
```

或者 Git：

```text
main
─────────────────────────→
      \          \
       branch A   branch B
```

---

# 十九、不同 Branch 可以拥有不同的“过去”

这是 Fork 最大的价值之一。

例如同一个问题：

```text
Branch A
recent = 20s
mode = language intent

Branch B
recent = 20min
mode = task analysis

Branch C
memory = 6 months
mode = historical comparison
```

因此 Fork 不仅是：

> 三种思考方式。

也是：

> 三种不同时间尺度。

---

# 二十、Context Builder

每次启动深度思考，并不是简单：

```text
copy current KV
```

而是动态构建：

```text
Branch Context =
Recent Exact Context
+
Current Mamba State
+
Retrieved Episodic Memory
+
Retrieved Semantic Memory
+
Pinned Information
```

例如：

```text
recent:
last 30s

memory:
route project

semantic:
user preferences

raw retrieval:
original design file
```

形成一个临时高分辨率工作上下文。

---

# 二十一、Branch 不应该复制无限 KV

Fork 应共享近期 Snapshot。

而远端历史按需召回。

例如：

```text
               Current Snapshot
                      │
       ┌──────────────┼──────────────┐
       ↓              ↓              ↓
    Branch A       Branch B       Branch C

Recent 30s       Recent 5min     Recent 10s
Spatial Memory   Project Memory  Constraint DB
```

因此 Fork 成本与：

> 当前工作记忆规模

相关，而不是：

> 整个 AI 一生经历的 Token 数量。

---

# 二十二、Branch 可以被现实信息打断

例如：

```text
用户：
帮我规划徒步路线

↓
Branch A 开始推理

3 秒之后：

用户：
等等，我膝盖受伤了
```

主世界线仍然在监听。

Controller 判断：

> 新信息会使旧 Branch 失效。

于是发：

```text
REBASE
```

或者：

```text
CANCEL
RESTART
```

因此 Signal 还应该包括：

```text
CONTINUE
PAUSE
INTERRUPT
REBASE
RESTART
CANCEL
MERGE
COMMIT
```

---

# 二十三、深度重启机制

Transformer 深度推理不应该只有：

> 开 / 关。

可以有几个层级：

### CONTINUE

继续当前思考。

### FORK

从 Snapshot 新开思路。

### REBASE

保留当前目标，但加载主世界线最新信息。

### RESTART

放弃已有推理状态，重新构建 Context。

### MERGE

多个 Branch 汇总。

### COMMIT

把结果写回主状态或长期记忆。

---

# 二十四、时间决定默认信息分辨率

长期记忆可以采用一个很自然的策略：

```text
现在
│
│██████████████████
│ 原始 Token
│
│██████████
│ Episode Detail
│
│█████
│ Latent Memory
│
│██
│ Semantic Memory
│
└────────────────→ 过去
```

即：

> 时间越近，默认分辨率越高。

时间越远：

> 默认越抽象。

但任何重要区域都可以被重新展开。

例如：

```text
RETRIEVE exact episode @ 3 months ago
```

重新从 Raw Archive 恢复高分辨率。

---

# 二十五、这类似一种“自适应认知分辨率”

整个系统不应该让所有信息拥有相同计算精度。

而是：

```text
重要 + 当前
→ 高分辨率

重要 + 远期
→ latent memory

不重要 + 远期
→ highly compressed

需要重新核验
→ raw retrieval
```

因此真正的 Context 不是一个固定长度的数组。

而是一张：

> **动态、多尺度的信息地图。**

---

# 二十六、输出端同样采用“惜字如金”

前面所有设计最终又回到最初问题：

> 为什么一定要通过大量语言 Token 思考？

模型真正需要对 Runtime 表达的很多时候只是：

```text
FORK
RETRIEVE
TOOL
RESTART
ANSWER
```

或者：

```text
route(A,B)
avoid=highway
prefer=scenic
```

而不是：

> “根据目前的情况，我认为用户可能希望……”

因此应该追求：

> **最大化每一个 Decode Token 的语义密度和行动密度。**

---

# 二十七、思考可以进入 Latent Space

进一步可以尝试：

```text
Hidden State
   ↓
Latent Iteration
   ↓
Latent Iteration
   ↓
Signal
```

而不是：

```text
Hidden State
   ↓
“首先我们分析……”
   ↓
“其次……”
```

这意味着：

> Token generation 从“思考时钟”降级为“通信编码”。

---

# 二十八、整个系统真正的无限对象和有限对象

系统中允许无限增长的东西：

```text
Raw History
Experience
Archive
Memory Index
```

不应该无限增长的东西：

```text
Transformer KV
Mamba State
Branch Working Context
Active Reasoning State
```

因此可以得到一条总原则：

# History can grow indefinitely.

# Active cognition must remain bounded.

中文就是：

> **经历可以无限增长，活跃认知必须保持有界。**

---

# 二十九、计算资源也变成动态的

Signal 不只是信息路由器。

它同时还是 Compute Scheduler。

例如：

简单事件：

```text
branch = 0
depth = 0
```

普通问题：

```text
branch = 1
depth = 4
```

复杂问题：

```text
branch = 3
depth = 12
```

极复杂问题：

```text
branch = 8
depth = 32
retrieve = long history
```

所以模型真正学习的是：

> **什么时候值得花计算。**

而不是：

> 所有输入都花同样的 FLOPs。

---

# 三十、最终系统角色划分

## Mamba / SSM

负责：

* 时间；
* 连续状态；
* 变化检测；
* 事件判断；
* Signal；
* 计算调度。

---

# 三十一、整个架构的一句话描述

这不是一个：

> 支持超级长 Context 的 Transformer。

而是：

> **一个持续存在于时间中的 AI：使用有界 Transformer 工作记忆观察当前世界，用 Mamba/SSM 维持长期连续状态和计算调度，将远端历史压缩成可检索的 Latent Memory，在重要事件出现时从当前认知主线 Fork 出多个具有不同时间范围、记忆范围和推理方式的 Branch，完成深度计算后再 Merge，并只有在真正需要与外部世界通信时才进行自回归 Token Decode。**

---

# 三十二、最核心的几个创新点

整套思想最终可以压缩成几个真正重要的变化：

**从 Context Window 转向 Memory Hierarchy。**

**从 Token Sequence 转向 Temporal Event Stream。**

**从 Always Decode 转向 Event-Driven Compute。**

**从单一路径推理转向 Branchable Cognition。**

**从无限 KV 转向 Bounded Working Memory。**

**从文本记忆转向 Latent Memory Object。**

**从统一时间尺度转向 Adaptive Temporal Resolution。**

**从自然语言控制转向 Neural Control Signal。**

---

# 三十三、最终哲学

传统 LLM 更像：

> 给它一堆文字，让它继续写文字。

而这里希望得到的系统更像：

> **一个一直处于世界中的计算主体。**

它可以：

* 听，但不说；
* 看到，但暂时不分析；
* 记住，但不放进工作记忆；
* 感觉到重要变化，再开始思考；
* 同时产生多条思路；
* 新现实出现时打断旧思路；
* 对远期记忆只保留抽象；
* 必要时重新展开原始证据；
* 最终只输出极少但高价值的信息。

因此这套架构真正想解决的问题不是：

> “怎么让模型拥有更多 Token？”

而是：

> **怎么让模型不再把 Token 当成认知本身。**

最终目标可以概括成一句：

> **让 AI 的经历是连续的，让注意力是稀缺的，让记忆是分层的，让思考是可调度、可分叉的，而让语言只成为必要时才使用的接口。**
