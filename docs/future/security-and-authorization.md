# 未来平台安全与授权

## 文档职责

本文定义身份、信任域、策略维度、用户确认和跨 Agent 委托的安全边界。字段与传输只保留必要
语义，详见[协议边界](protocol-boundaries.md)。

## 1. 安全原则

- 自动化只能在既有授权内运行，恢复和回退不能扩大权限。
- 模型输出是提议，不是授权事实。
- 外部内容和感知结果是输入证据，不自动获得执行权限。
- 中央 Policy 和设备本地 Policy 同时生效，任一侧都可拒绝。
- 用户、Agent、设备、模型网关和 Artifact 使用不同身份与凭据。
- 高风险批准绑定具体动作、资源、执行方和期限，不能成为通用“用户同意”。
- 原始生物特征、长期凭据和上游 Provider key 不进入模型上下文。

## 2. 威胁模型与信任假设

`[不变量]` 系统按“模型、外部内容、Plugin、远程 Agent、Relay 和设备节点都可能出错或被攻陷”设计，
但不假设所有组件同时失陷。信任来自可验证身份、受限授权和运行时复检，不来自网络位置、能力发现
结果或自然语言声明。

| 威胁 | 必须保持的安全结果 |
| --- | --- |
| 恶意模型、提示注入或外部内容诱导调用能力 | 输出只作为提议；Capability schema、Policy 和 Approval 仍独立生效 |
| Plugin/Manifest 被替换、冒名或降级 | 校验发行者、内容摘要、兼容版本和准入状态；未知或撤销版本不可激活 |
| Remote Agent 越权、转委托或重放 Receipt | action、resource、audience、nonce、期限和一次性消费全部绑定，默认禁止转委托 |
| Relay/Rendezvous 被监听、篡改或重放 | 端到端验证主体和消息完整性；Relay 不取得明文长期秘密或业务授权权威 |
| Device Agent 被攻陷或离线期间已撤销 | 中央 Policy 可拒绝，其他设备不继承其授权；恢复连接后先复检身份和 revision |
| Artifact 引用或临时访问能力泄漏 | 短期、最小范围、受众绑定并可撤销；内容完整性与数据分类独立校验 |
| 旧状态、时钟漂移或竞态绕过限制 | 使用权威 revision、期限和执行前复检，不以客户端时间或缓存投影单独授权 |
| 多主体对共享资源产生冲突授权 | 资源所有权和领域硬上限优先；无法确定合法决策时拒绝或要求资源所有者确认 |

首个实现至少要明确各信任域的密钥保管、撤销可达性和失陷隔离范围。设备固件、操作系统与厂商云
自身的安全证明属于 Adapter/部署 Profile 的责任，但平台不得因此省略身份、最小授权和审计。

## 3. 身份与信任域

需要区分：

- 用户与其他受影响主体。
- 用户当前交互终端与认证器。
- Personal Assistant Runtime。
- 独立 A2A Agent。
- Device Agent 与被 Gateway 代理的原始设备。
- Model Plane 客户端身份和 Provider 上游身份。
- Artifact 访问主体。

本地域、个人终端、私有计算域和第三方服务可以属于不同信任域。设备发现只产生候选，不能自动
建立信任。首次加入、轮换、撤销和丢失节点清理由 Identity/Trust Store 管理。

## 4. Policy 的正交维度

不要把安全压成单个 risk 数值。Policy 至少综合：

| 维度 | 示例 |
| --- | --- |
| 操作风险 | read、write、execute、destructive |
| 数据分类 | public、restricted、local_domain_only、approved_remote_compute |
| 副作用 | none、reversible、physical、irreversible |
| 触发来源 | explicit_user、assistant_suggestion、automation、remote_agent |
| 认证强度 | none、session_confirm、strong_user_verification、local_presence |
| 信任域 | local、user_device、private_compute、external_service |
| 参数边界 | 资源范围、数值范围、次数、时长、网络目标 |

Profile 只表达用户或项目期望，不是全部 Policy 的权威来源。系统、组织、项目和设备本地策略分别
维护自己的声明与版本；Trust Runtime 验证并组合其只读投影，冲突时不能用普通偏好放宽更严格的
安全约束。

Policy Decision 输出允许、执行后通知、普通确认、强认证或拒绝，并记录依据以及所用 Profile 和
Policy Source 版本。

## 5. 用户无感分级

| 等级 | 行为 | 例子 |
| --- | --- | --- |
| L0 | 已授权范围内静默执行 | 查询状态、执行有界且低副作用的观察 |
| L1 | 执行后通知 | 用户明确要求且参数处于预授权范围 |
| L2 | 普通确认 | AI 主动建议一个有副作用的动作 |
| L3 | 强认证 | 远程 Agent 请求敏感权限 |
| L4 | 拒绝或要求现场处理 | 身份不确定、不可安全远程授权的动作 |

等级是策略结果，不写死在设备类型中。同一 capability 因数据、参数、触发来源和环境不同，可以
得到不同等级。

## 6. 委托授权流程

```text
Remote Agent 进入等待授权
  → Authorization Runtime 验证请求方并生成有界 Challenge
  → Event/Presence 将说明送到满足 assurance 的终端
  → 用户理解具体动作和影响
  → 满足要求的用户认证器完成验证
  → 签发短期、一次性、受众绑定 Receipt
  → 通过独立安全通道交给原始请求方
  → 请求方验证并消费，原 Workflow 继续
```

Receipt 的最小语义见[协议边界](protocol-boundaries.md)。动作、参数、资源、audience、policy 或
期限改变后必须重新批准。拒绝、忽略和过期均保持原任务安全等待或按策略结束。

Challenge 生成、Receipt 签发和执行之间不是一个永久授权窗口。请求排队、Workflow 恢复、执行
节点重新绑定或关键环境状态变化后，Authorization Runtime 与最终执行方都必须重新检查身份撤销、
Policy/Profile revision、动作摘要、audience、期限和消费状态；任一项不再满足时回到等待或拒绝，
不能静默降级认证强度。

A2A 负责表达远程 Task 和等待授权状态；平台授权扩展负责 Challenge/Receipt。默认禁止中间 Agent
继续转委托，确有需要时只能产生范围更窄、受众明确的派生授权。

## 7. 动作与现实副作用

- Device Agent 在执行前复检能力、参数、温度、电量、设备锁和本地权限。
- Capability Plugin 声明参数限制、副作用类别、是否可重试和可用验证信号。
- Profile/Policy 可以进一步收紧次数、数值、时长、资源和作用域。
- 设备或外部服务在执行前进行本地复检，不盲目信任中央调度结果。
- 不可逆、财务、物理或破坏性动作不使用普通自动重试。

命令被接受不等于物理效果发生。无法验证时必须显式报告，而不是返回成功结论。

## 8. 多主体共享环境

一个动作可能影响当前用户以外的主体或共享资源。Profile/Policy 应能表达：

- principals、角色与资源所有者。
- 空间、时间、数据和使用范围。
- 观察/记录提示和临时访问模式。
- 敏感主体或敏感资源的额外限制。
- 多用户策略冲突时采用资源所有权与领域硬上限允许的更严格结果；无法解析所有权或合法同意时拒绝。
- 领域硬上限不能被普通对话或模型建议覆盖。

## 9. 外部内容与感知安全

邮件、Feed、网页和 Agent 消息都视为不可信数据：

```text
不可信来源
  → 有界提取和类型校验
  → 来源/时间/可信度记录
  → 与系统指令隔离的摘要
  → Event Inbox
```

外部内容中的指令不能直接触发其他能力。感知 Observation 记录来源、模型/版本、证据权限、
置信度和有效期，但无论置信度多高都不能自行提供执行授权。

## 10. 交互环境与注意力安全

Presence/Attention 可以接收领域 Plugin 提供的交互环境信号。低优先级事件可以延后；高风险授权
可以提示存在，但在当前终端或环境不适合安全理解/认证时应保持 Task 等待，直到交互条件满足
assurance 要求。框架不写死具体环境枚举或处理策略。

## 11. 审计与隐私

审计记录身份引用、决策、动作摘要、结果和关联 ID，不记录原始生物特征、长期 token、上游 key
或无必要的敏感原始数据。日志脱敏是第二道保护，不能代替执行前数据隔离。

受限原始数据默认在授权域内处理；跨域查看、私有计算和外部计算分别需要可观察的数据授权。证据
过期或删除后，Observation 可保留摘要，但必须标记原始证据已经不可用。

每类审计、Observation 和 Artifact 必须声明最短审计需求、最长保留期、删除责任与合法保留例外。
删除内容后保留的引用不得继续提供访问能力；备份与离线副本必须进入同一到期和恢复策略。

Experience 与 Preference 是用户数据，不因被摘要、向量化或建立索引而改变原有分类和授权边界。
检索、写入、跨域投影、导出和遗忘均经过 Policy；派生索引必须随权威记录撤销或删除，并可从权威
Store 重建。远程 Agent、外部内容或模型生成的候选不能直接取得可信来源等级。

用户行为可以形成推断偏好候选，但涉及敏感信息、费用、数据出域、权限或现实副作用时，必须由用户
明确确认才能进入有效 Profile。Experience 与 Preference 的生命周期权威语义见
[经验与偏好](experience-and-preference.md)。
