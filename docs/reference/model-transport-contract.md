# 模型传输接口契约

## 文档职责

本文档定义模型客户端与模型访问端点之间的稳定传输边界和请求生命周期。
客户端可以是命令行 Agent、服务、独立 SDK 或其他应用；访问端点可以是直连模型服务、兼容网关、
远端 provider、本地推理引擎，或在推理前后执行优化、编译、缓存与调度的模型运行框架。

本文档不评价模型正文质量，不绑定具体项目、部署方式、provider 或推理框架。

## 稳定边界

模型客户端负责：

- 组装自身需要的指令、输入、历史、工具或其他模型上下文；
- 为每一次传输尝试生成独立请求 ID；
- 决定客户端等待时限、重试和停止条件；
- 消费所选模型协议的响应。

客户端可以选择普通 JSON 响应或 SSE 流式响应。传输流式与编排流式是两个独立能力：模型客户端
可以逐块接收并向观察者转发增量，但只有在完整响应组装并通过协议校验后，才把一次语义回复交给编排层。
这样 SDK 可以提供实时展示，同时不会让不完整 JSON 或半个工具调用提前驱动 Agent 行为。
面向人的流式观察器只投影显式自然语言字段；动作、工具名称和参数始终留在完整响应校验路径中。
兼容端点可能把自然语言放在严格 JSON 正文的顶层字段中，也可能在使用原生工具调用协议时直接放入
纯文本 `content`。观察器应识别这两种合法形态并流式投影自然语言，但不得把 JSON 中的动作字段、
原生工具调用增量或旧式工具协议标签暴露到展示通道。

流式客户端必须区分三类等待边界：

- 建连或首包时限：限制端点没有开始响应的等待时间；
- 流空闲时限：SSE 开始后，每收到一个有效传输块就重新计时，只用于发现停止产出或断开的流；
- 最大流持续时间：独立的安全上限，防止持续发送数据但永不结束的响应无限占用资源。

普通 JSON 响应仍可以使用单次请求总时限。不得把 SSE 的流空闲时限实现为从请求开始计算且不刷新的
固定截止时间，否则仍在正常产出的长回复会被误判为超时。

模型访问端点负责：

- 将请求路由到配置的模型后端；
- 仅在入口协议与后端原生协议不同时执行必要转换；
- 在协议相同时保持请求和响应正文透明传递；
- 将客户端关联 ID 传入诊断链路并在响应中回显；
- 客户端断开时取消对应后端工作，避免失去接收者的推理继续占用资源。

模型正文是不透明数据。只要外层协议结构合法，传输层不因语言混杂、措辞质量或内容随机性修改正文。
是否进行安全、业务或质量评估，由调用方通过独立、显式、可替换的策略层决定。

## 请求关联

每次传输尝试可以发送：

- `X-Client-Request-ID`：客户端生成的一次尝试唯一标识；重试使用新值。
- `X-Client-Timeout-Ms`：客户端本次尝试的最大总时限，仅用于诊断和协调。
- `X-Client-Idle-Timeout-Ms`：流开始后的最大无数据间隔；非流式客户端可以不发送。

访问端点回显 `X-Client-Request-ID`，并在后端诊断日志中记录同一标识。`X-Request-ID` 等由服务端
或 provider 生成的标识独立记录，不参与客户端关联 ID 的一致性判断。客户端关联 ID只对应一次传输尝试，
不绑定任何具体会话、任务或应用的数据模型。

## 取消与重试

客户端超时会关闭当前 HTTP 响应连接。访问端点观察到请求中止或响应连接在完成前关闭时，
取消对应后端工作。客户端拥有重试决策；每次重试是独立尝试。

面向人的增量在完整回复通过校验前都属于临时展示。若一次已经展示自然语言的尝试失败，调用方必须
清除可替换界面中的临时内容，或在不可回写的终端中明确标记该段内容已中止且未被采纳，再开始重试。
失败尝试的增量不得写入正式会话消息，也不得与下一次尝试拼接。

传输中间层默认不自行重试普通模型请求，避免与客户端重试叠加。后端适配器如果执行协议兼容降级，
应保留同一请求 ID并明确记录降级过程。

## 可观测性

每次尝试至少记录开始和一个终态；终态包括完成、上游错误、网络失败和客户端取消。诊断信息按实际后端协议提取：

- 请求 ID、协议、后端地址、状态和耗时；
- 流开始时间、首个和最后事件时间、事件数、自然语言投影形态、可见自然语言字符数和终止原因；
- 可获得的端点或后端响应 ID、停止原因和资源用量；
- 模型正文的长度、哈希和限长预览；
- 结构化工具调用名称或等价动作摘要。

非流式和流式请求遵守相同的开始/终态约束。日志摘要不得参与或改变真实响应。生产环境默认不保存完整
模型正文；诊断可以通过限长预览和哈希完成链路对照。

发生协议转换时，访问端点分别记录后端原始响应摘要和面向客户端的组装响应摘要。调用方继续记录其
收到的响应及解析结果，三者使用同一客户端请求 ID，从而能够区分模型生成、协议转换和调用方解析问题。

## 扩展原则

- 客户端只依赖模型协议和传输元数据，不依赖某个网关实现。
- 访问端点通过后端适配器接入托管 API、本地推理服务器、推理优化器、模型编译器和资源调度器。
- 路由、鉴权、限流、缓存、批处理、量化选择和硬件调度属于可组合能力，不写入基础正文协议。
- 后端能力通过独立元数据或能力发现接口声明，不根据服务名称猜测。
- 新能力优先扩展现有请求生命周期和适配器接口，避免为特定客户端建立旁路。
