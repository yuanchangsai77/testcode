# testcode v0.2

本文档是 `testcode` v0.2 的版本快照，重点说明它相对
[v0.1](v0.1.md) 的升级。v0.1 已具备模型调用、基础工具、安全审批、会话保存和运行
日志；v0.2 在此基础上补齐真实编码任务需要的项目感知、可靠编辑、能力扩展和原生交互。

能力边界固化后不再回改。后续版本通过新快照记录变化；实现过程由 Git 历史追溯。

- 文档固化日期：2026-07-31

- v0.2 能力基线提交：`e8024f6f3aa3e3e1eebd8e4ddcda1ceb88b5c098`
- 对应项目版本：`0.2.0`

- 完整对比：`85375b0fd064f969e69f5b41cd9d889634c29e4c...v0.2.0`

## 一句话升级

v0.1 是“模型能够调用本地工具”的基础闭环；v0.2 是“能够理解项目、可靠修改并验证、
按需接入外部能力，同时提供可持续交互体验”的本地 Agent runtime。

## v0.1 → v0.2 总览

| 维度 | v0.1 | v0.2 | 升级价值 |
| --- | --- | --- | --- |
| 项目上下文 | 主要依赖用户 prompt 和工具读取 | 自动加载项目规则、相关 workspace 摘要和显式 context | 减少模型盲查目录和遗漏项目约束 |
| 项目识别 | 无统一探测器 | 统一识别 Python、Node.js、Rust、Go | workspace 摘要与测试命令使用同一事实来源 |

| 测试 | 执行用户给出的测试命令 | 可解析唯一可靠的默认命令和 Python 环境 | 修改后更容易形成自动验证闭环 |
| Agent 循环 | 基础模型—工具循环 | 重试、重复动作去重、进度纠偏和明确停止条件 | 减少重复读取、无限循环和无效重试 |
| Shell | 单次命令执行 | 会话级串行 Bash、cwd/env 保留、进程组清理 | 支持连续命令并可靠处理中断与超时 |
| 安全 | 风险等级与执行审批 | 增加凭据写入阻断、日志脱敏和破坏性风险提升 | 用户批准也不能把真实秘密写入仓库 |
| Skill | 无 | 内置、全局、项目 Skill，metadata 扫描与按需激活 | 专项工作流不必永久占用模型上下文 |
| 外部工具 | 仅内置 registry | 能力仓库、渐进披露和 MCP 三种 transport | 外部能力按需连接、发现和激活 |
| 配置 | `.env` 模型连接配置 | 分层 TOML、MCP server、重试/轮数/输出限制与硬上限 | 运行策略可以配置且不会无限占用资源 |
| 交互 | 基础逐行 CLI | 原生 inline TUI、编辑器、补全、审批和运行时输入 | 保留 scrollback、选择复制与实时任务控制 |
| 会话恢复 | 保存对话并按 id 恢复 | 增加 run trace、resume state、active Skill/capability | 恢复时能看到更完整的执行背景 |
| 可观察性 | 基础 run 事件和详情日志 | 增加安全、项目、能力仓库、MCP 和 TUI 事件 | 故障和决策链路更容易复盘 |
| 测试 | 覆盖基础 engine、model、policy 和 tools | 369 个测试覆盖全部关键子系统 | 从基础闭环提升为系统级回归保护 |

## 核心升级一：从“能改文件”到“可靠编码闭环”

### v0.1

- 模型可以读取文件并生成 unified diff。
- patch 校验路径和上下文。
- 测试工具执行显式命令。

### v0.2

- 修改已有文件前必须先通过 `read_file` 建立 read state。
- read state 记录 path、mtime 和 sha256；patch 前重新校验。
- 文件被外部修改时返回 `file_changed_since_read`，要求重新读取。
- patch 返回 preview、changed files 和增删行统计。
- patch 限制单次文件数和 diff 行数，并细分语法、上下文、路径和文件状态错误。
- 测试失败会回到模型循环继续修复；连续失败达到边界时明确停止。
- `run_tests` 记录命令来源、环境来源、项目根目录、耗时和通过状态。

### 用户影响

v0.2 不再允许模型仅凭旧上下文直接覆盖现有文件。相比 v0.1，这是一项有意的行为收紧：
模型需要重新读取发生变化的文件，但能显著降低覆盖并发修改和错误 patch 的风险。

## 核心升级二：从“手动提供上下文”到“项目感知”

### 项目规则

- 从工作目录向上查找 `AGENTS.md`。
- 在项目边界内按根目录到近目录的顺序加载，近目录规则优先。
- 单个规则文件具有读取上限，避免规则撑满上下文。

### Workspace 摘要

- 仅在请求确实与项目相关时启用。
- 收集项目标记、Git branch/status/latest commit、建议测试命令和有界目录树。
- 忽略 `.git`、虚拟环境、依赖、缓存和构建产物。
- 普通外部查询不会因为出现 `code`、`test`、`project` 等歧义词就扫描仓库。

### 显式 context

- `--context` 可重复传入文件、目录和 glob。
- 路径必须位于 workspace 内。
- 二进制文件拒绝注入，文本读取受文件数量和字节数限制。
- prompt 中保留来源，让模型区分自动上下文与用户指定内容。

### 统一项目探测

| 项目标记 | 项目类型 | 可靠时解析的测试命令 |
| --- | --- | --- |
| `pyproject.toml` | Python | `python -m pytest` |
| `package.json` | Node.js | `npm test` |
| `Cargo.toml` | Rust | `cargo test` |
| `go.mod` | Go | `go test ./...` |

只有一个可靠候选时才自动执行。没有候选返回 `test_command_not_detected`，多个候选返回
`test_command_ambiguous`；v0.2 不在多项目工作区中擅自猜测。

## 核心升级三：从“固定工具列表”到“能力仓库”

v0.1 的模型工具主要来自启动时注册的内置 registry。v0.2 将“系统知道的能力”和“当前
模型可见的能力”分开：

```text
能力仓库
  → 查看外层目录
  → 打开相关工具箱 manifest
  → 激活少量叶子能力
  → 下一模型轮次可见
  → 使用后释放或按 scope 保留
```

能力仓库新增：

- `warehouse_list`
- `toolbox_open`
- `capability_activate`
- `capability_release`
- `capability_status`

activation 支持 `turn`、`run`、`session` scope，并受数量和字符预算约束。批量激活会
预检名称冲突、manifest 归属和预算；失败时原子拒绝，不留下部分注册状态。

### Skill

- 支持包内置 Skill、`~/.testcode/skills/` 和项目 `.testcode/skills/`。
- 启动时只扫描 metadata，不加载全部正文。
- 项目同名 Skill 覆盖全局和内置版本，全局版本覆盖内置版本。
- 打开 Skill 工具箱只显示 instructions manifest。
- 激活后正文从下一轮进入 prompt。
- active Skill 和 capability id 可以跨多轮 session 保留。
- 内置 `git-helper` 与 `pytest-helper` 验证完整链路。

### MCP

v0.2 首次加入完整 MCP 主链路：

- `stdio`
- `streamable_http`
- `sse`
- initialize 与协议版本校验
- tools list/call
- resources list/read
- 懒 discovery
- 内存与磁盘 cache
- 失效 client 一次重建
- schema/result 适配
- 稳定命名与名称冲突诊断
- capability traits、默认风险映射和配置 override
- MCP 专项事件与错误码

配置 MCP server 不会立即连接或把全部工具注入模型。只有模型打开对应工具箱时才
discovery，选中的叶子工具显式激活后才进入 registry。

## 核心升级四：执行安全从“授权”扩展到“内容”

v0.1 已有 `readonly`、`confirm`、`auto` 和 risk-based approval。v0.2 保留兼容模式，
并增加独立的写入内容安全层：

- `patch` 只扫描新增行，允许删除仓库中已有的秘密。
- 兼容工具 `apply_change` 扫描完整拟写入内容。
- `shell_exec` 扫描字面命令作为补充防线。
- 识别私钥头、常见供应商令牌、云访问密钥、Bearer Token、URL 凭据和敏感字段赋值。
- 环境变量引用和明确占位符不会按真实凭据阻断。
- 命中后返回 `blocked_by_security_policy`，用户审批不能绕过。
- 结果、metadata 和日志只记录类别与位置，不回显秘密原文。

Shell 中的递归强制删除、`git reset --hard`、强制目录清理和系统路径重定向会提升为
`destructive`。非破坏性审批可在同一 run 内复用，破坏性动作每次单独确认。

## 核心升级五：Agent 循环能够纠偏和停止

v0.2 为模型—工具循环增加以下控制：

- 模型请求支持可配置重试次数和延迟。
- 最大模型轮数从代码边界和配置双重限制。
- 相同工具名与规范化参数生成稳定动作指纹。
- 同一写入世代内的相同成功动作不会再次执行。
- 成功写入会清空旧读取指纹，允许重新检查变更后的文件。
- 修改请求重复调用相同只读工具时产生 `progress_required`。
- 连续三轮测试失败时停止。
- 连续两轮只有不可重试结果时停止。
- 新激活工具从下一模型轮次可见，避免同轮工具集合漂移。

这些控制减少了 v0.1 中可能出现的重复读取、无效重试和长时间无进展循环。

## 核心升级六：从逐行 CLI 到原生 inline TUI

v0.2 的交互式 TTY 使用项目内原生 backend：

- 不进入 fullscreen/alternate screen。
- 不启用鼠标报告，保留终端原生滚轮、选择和复制。
- 稳定内容只写入 scrollback 一次。
- 程序只重绘底部瞬态活动区。
- 支持 UTF-8、宽字符、组合字符、多行编辑和 bracketed paste。
- 支持会话内输入历史、Slash Command 自动补全和历史 session 选择。
- Working、工具、审批、取消和运行时输入通过有界事件队列与集中状态渲染。
- 运行期间可编辑下一条消息；提交后中断当前 run 并排队。
- resize、Ctrl+C、EOF 和异常退出恢复终端状态。

`--once`、重定向、CI 和非 TTY 环境继续使用 plain presenter，保持脚本兼容性。

## 配置、会话与可观察性

### 配置

v0.1 主要通过 `.env` 提供模型连接信息。v0.2 新增：

- `~/.testcode/config.toml` 用户默认配置。
- `.testcode/config.toml` 项目覆盖配置。
- 模型重试次数与延迟。
- 最大模型轮数。
- MCP server 与 transport 字段。
- MCP 工具数、active capability、输出字节、读取字节和搜索结果限制。
- 所有可调资源限制具有代码内硬上限，超限明确报错。

现有 `.env` 模型连接方式继续兼容。项目同名 MCP server 整体替换全局条目，敏感值可以
通过 `${VAR}` 引用进程环境变量。

### 会话

除 v0.1 的 messages、cwd、状态和时间戳外，v0.2 还保存：

- run ids
- active Skill
- active capability ids
- bounded run/turn trace
- 派生 resume state
- 最近结果和恢复提示所需摘要

旧 session 缺少新增字段时按空值兼容加载。

### 可观察性

在基础 model/tool/safety 事件之外，v0.2 增加：

- 内容扫描与阻断事件
- 项目探测与测试命令解析事件
- Skill 扫描与激活信息
- 能力仓库打开、激活、释放和状态事件
- MCP transport、discovery、cache、调用和生命周期事件
- TUI model/tool/approval/cancel 生命周期

### 内置工具变化

## 兼容性与升级说明

### 保持兼容

- Python 最低版本仍为 3.11。
- `python -m testcode` 和 console script 入口保持不变。
- v0.1 的 `.env` 模型连接变量继续有效。
- `--once` 仍提供非交互单轮运行。
- v0.1 session 的基础字段可以继续加载。
- 内置工具名称保持稳定，`patch` 仍是主要编辑工具。

### 有意变化

- 修改已有文件前必须读取；未读 patch 会被拒绝。
- 读后文件发生外部变化时必须重新读取。
- 自动测试只在候选唯一且可靠时执行。
- 交互式 TTY 默认进入 inline TUI；非 TTY 保持 plain 输出。
- 外部 MCP 与 Skill 不再默认全部进入模型上下文，需要通过能力仓库激活。
- 高置信度凭据写入即使经过用户审批也会被阻断。

### 从 v0.1 升级

```bash
git fetch --tags origin
git checkout v0.2.0
python3 -m venv .venv
.venv/bin/python -m pip install -e .
.venv/bin/testcode --version
```

已有 `.env` 可以继续使用。需要运行策略或 MCP 时，再创建
`~/.testcode/config.toml` 或项目 `.testcode/config.toml`；不需要为 v0.2 强制迁移
配置。
